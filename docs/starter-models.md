# First-use model portraits

Eligibility is decided from the current personal model inventory independently for women and men. A saved model blocks automatic generation only for its own gender. Deleting the last model of that gender permits a fresh trio on a later detection; historical enrollment flags do not block it. Existing slots are reused by the server's atomic reservation RPC.

`POST /api/model/starter-models` accepts `userId`, `gender` (`woman` / `man`), and optionally `retrySlot` (0–2). The corresponding web route is `/api/modelWeb/starter-models`. `GET` with `?userId=` resumes queued work and returns the six-or-fewer ordered slots plus `eligibleByGender`. The server owns prompts, enrollment and provider selection. All three slots use the original general fictional adult Vogue-style casting brief explicitly requesting a 22-year-old professional high-fashion model, with high cheekbones, defined bone structure and a refined jawline. Hair, skin, eye and nose combinations are no longer prescribed; manual text portraits also use the original general casting direction. Each text request retains a fresh random seed. No file comparisons are performed. Saved-model recovery remains idempotent and does not regenerate a portrait. Native identities use registered `public.users` IDs; when auth middleware supplies a verified web user, it must match `users.supabase_user_id`.

Manual text and automatic starter portraits use `fal-ai/nano-banana-2`, 1K, 3:4, JPEG, one image per request. User-supplied reference photos use `fal-ai/nano-banana-2/edit` with the same output settings; an edit failure never falls back to inventing an identity. The user's latest instruction replaces both the prior Sunburst text portrait route and NB Lite reference route. Try-on/product generation and its V1 Sunburst/Pruna finishing are unchanged. Provider safety defaults are retained.

The new RLS-protected tables and RPC are service-role-only. Slots have a unique `(user_id, gender, slot)` key and a nullable model reference with `ON DELETE SET NULL`. A removed portrait keeps its slot until the current-inventory reservation RPC decides whether to reuse it. Atomic claims prevent parallel app/web requests from duplicating work. Successful portraits join the existing private `user_models` library. Failed slots retry only on explicit user action, with at most three attempts. Active workers renew a processing lease every 20 seconds. A lease older than 90 seconds becomes retryable after a process interruption, without automatically charging for another generation. Naming is capped at 60 seconds and portrait generation/storage at 330 seconds; cancellation and claim checks prevent late completions from saving into expired attempts. A saved portrait is recovered without another provider call.

RN phone, tablet and Mac share the same hook as web (copied within the separately built projects, equality tested). Only successful gender detection triggers enrollment; classifier fallbacks do not. Processing portraits occupy stable slots in the existing library and use the completed card frame with a static blurred local placeholder and a small top-right spinner; there is no moving light sweep. Slot zero is the default as soon as ready; an explicit selection, including Random, wins over async completion. Last choices are stored by user and gender in AsyncStorage/localStorage, with compatibility for the old native selected-model ID.

Native and web requests include the selected interface `languageCode` in both GET query parameters and POST bodies. Before creating portraits, a bounded JSON text task (512 output tokens, 20-second provider request timeout) receives instructions to produce three distinct contemporary first names in that language, respecting the region and native script. The prompt contains no example names or fixed name catalog. New batches exclude current model names, retained slot names and up to 90 recent names per owner held in bounded server memory. Each naming attempt gets a new variation token; repeated suggestions are rejected and retried. Retrying the same already-named portrait preserves its saved name. Validated names are saved to `model_starter_jobs.display_name` before portrait generation and retained across retries and restarts. Invalid name responses retry once, then expose the existing explicit retry state without calling the portrait provider. Portrait prompts stay independent of these names.

Validation: backend concurrency/retry tests, React hook flow tests, all 70 locale catalogs, web test suite, web desktop/tablet/mobile mock responses and native Metro compilation. The migration was applied and transaction-rollback checks verified eligibility and duplicate prevention. No paid Fal generation was made during this validation. Backend application changes still require deployment before the new routes/provider selection are active remotely; the added tables alone do not start work.

New automatic models receive editable fictional measurement presets in `model_profile`: women 178 cm / 84–62–90 cm; men 188 cm / 98–78–96 cm (height / chest–waist–hips). Only these four numeric fields are populated. They are not inferred measurements and never enter the portrait prompt or provider input. Completed-job snapshots include the profile so all clients receive it immediately. Existing saved profiles are preserved during recovery.

## Model pool (10 Sep 2026)

`model_pool` holds shared models clipped from Pinterest by the Chrome extension (`POST /api/model/starter-models/pool/clip`, native router only; body `imageBase64|imageUrl`, optional `gender`, `languageCode`, `regionCode`, `fingerprint`). Creation reuses the manual reference-photo path: upload → Gemini analysis (name/age/gender) → `nano-banana-2/edit` ID portrait → row with the fictional measurement preset. Duplicate fingerprints return the existing row.

Assignment (`model_pool_assignments`): on every `GET /starter-models` (and on `POST` when the pool has ≥3 active models of the requested gender) the server assigns three random pool models per gender **once** and copies them into the user's `user_models` library (`replicate_id = pool:<poolId>:<userId>:s<slot>`), so the generation pipeline, selection and deletion work unchanged. The snapshot appends them as virtual completed jobs in slots 3–5 (`pool: true`, `poolModelId`). Existing user models are never removed; clients sort cards by `created_at`, so pool copies list after older models. When the pool has ≥3 models the fal portrait trio is no longer generated for new users; an empty pool falls back to the previous flow.

`POST /starter-models/shuffle { gender }` replaces the three assignments with unseen models (`model_pool_history`; resets when exhausted) and deletes only the previous pool copies. `GET /starter-models/pool?gender=&page=&limit=` lists the pool with `assignedPoolIds`. `POST /starter-models/pick { poolModelId }` copies a chosen model into the library (`…:pick`) and returns it; the shared hook selects it. `GET /starter-models/pool/stats` returns per-gender counts (used by the extension's connection test). Tables are RLS-enabled, service-role only (`migrations/add_model_pool.sql`, applied 10 Sep 2026).
